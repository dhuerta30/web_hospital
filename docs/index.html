A Artify v1.x

Comenzar

El framework Artify

Artify es un framework PHP a medida, con patrón MVC, pensado para construir aplicaciones de gestión y mantenedores CRUD con muy poco código. Da soporte al sitio institucional y a las herramientas internas del Hospital San José de Melipilla.

Esta documentación está dirigida a quien deba mantener o extender el proyecto. Asume conocimiento de PHP y de un framework MVC (si vienes de Laravel, la estructura te resultará familiar).

Piezas principales

  • ArtifyRouter — enrutado desde un único index.php.
  • Queryfy — constructor de consultas sobre PDO con sentencias preparadas.
  • Artify CRUD — generador de grillas: tablas, formularios, validación y cargas.
  • ArtifyStencil — motor de plantillas para las vistas.
  • Security — capa central de seguridad (cabeceras, sesión, CSRF, cargas).
  • arco — consola de línea de comandos para generar controladores y modelos.

Stack y dependencias

PHP 8.x, PDO (MySQL/MariaDB), Composer para autoload y dependencias, y un front-end sobre Bootstrap. El desarrollo local usa Laragon; el despliegue es en cPanel/Linux.

Documento vivo. Amplía cada sección a medida que el framework evolucione: esta guía es también la evidencia de mantenibilidad que respalda la continuidad del proyecto.

Comenzar

Arquitectura y estructura

Todo el tráfico entra por index.php (front controller), que arranca la seguridad, resuelve la ruta y delega en un controlador. El controlador usa modelos y Queryfy para los datos, y devuelve una vista renderizada con ArtifyStencil.

Estructura de carpetas

/
├─ index.php            # front controller: boot + rutas
├─ .env                 # configuración y credenciales (NO se publica)
├─ arco                 # consola CLI (generadores)
├─ app/
│  ├─ core/             # ArtifyRouter, ArtifyStencil, SessionManager, Token, DB, Security
│  ├─ Controllers/      # controladores de la aplicación
│  ├─ Models/           # modelos
│  ├─ Views/            # plantillas
│  └─ libs/artify/      # librería Artify + Queryfy + cargas
└─ servidor/            # config de referencia (FUERA del webroot)

Flujo de una petición

  1. El servidor reescribe todas las URL hacia index.php (ver Despliegue).
  2. Security::boot() aplica cabeceras, cookies seguras y ocultamiento de errores.
  3. ArtifyRouter compara la URL con las rutas declaradas y ejecuta el método del controlador.
  4. El controlador consulta datos con Queryfy o con Artify CRUD.
  5. Se devuelve HTML renderizado con ArtifyStencil, o JSON para las llamadas AJAX/API.

Comenzar

Instalación y entorno

Clona el proyecto, instala dependencias y configura el archivo .env. En local se trabaja con Laragon (Apache + PHP + MariaDB).

Puesta en marcha local

# 1. dependencias
composer install

# 2. copia y edita la configuración
cp .env.example .env

# 3. sirve el proyecto (Laragon) y visita el host virtual

Variables de entorno

El .env centraliza configuración y credenciales. Nunca se sube al control de versiones ni queda accesible desde el navegador.

ClaveDescripción
BASE_URLURL base de la aplicación, usada para redirecciones y assets.
APP_DEBUGtrue en desarrollo; false en producción (oculta errores).
ENABLE_JWTAUTHActiva la autenticación por token en la API REST.
ALLOW_QUERY_EXECUTIONDebe ser false: desactiva el modo de SQL crudo en la API.
Seguridad. En producción define APP_DEBUG=false y ALLOW_QUERY_EXECUTION=false. Ver Seguridad.

Núcleo

Enrutado

Las rutas se declaran en index.php sobre una instancia de ArtifyRouter. Cada ruta asocia un verbo HTTP y un patrón de URL a un método de controlador.

index.php

require 'vendor/autoload.php';

use App\core\Security;
use App\core\ArtifyRouter;

Security::boot();            // cabeceras, cookies, errores

$router = new ArtifyRouter();
$router->get('modulos', [HomeController::class, 'modulos']);
$router->post('login',   [LoginController::class, 'index']);
$router->run();

Parámetros de ruta

Los segmentos dinámicos se capturan y llegan como argumentos del método.

$router->get('usuario/{id}', [UserController::class, 'show']);
// public function show($id) { ... }
Despliegue en subcarpeta. Si el sitio no está en la raíz del dominio, ajusta BASE_URL y el mod_rewrite; ver Despliegue.

Núcleo

Controladores

Un controlador agrupa métodos que responden a rutas. Viven en app/Controllers y se generan con la consola arco.

namespace App\Controllers;

use App\core\DB;
use App\core\SessionManager;

class NoticiasController
{
    public function __construct()
    {
        SessionManager::startSession();
        if (!SessionManager::get('usuario')) {
            Redirect::to('login');   // guardián de sesión
        }
    }

    public function index()
    {
        $artify = DB::ArtifyCrud();
        echo $artify->dbTable('noticias')->render();
    }
}
Regla. Todo controlador de administración debe validar la sesión en su constructor. Ver Sesión y autenticación.

Núcleo

Modelos

Los modelos encapsulan el acceso a una tabla o a una consulta concreta. Se apoyan en Queryfy para no escribir SQL a mano.

namespace App\Models;

use App\core\DB;

class UserModel
{
    public function select_users()
    {
        $q = DB::Queryfy();
        return $q->select('usuario');
    }
}

Genera el esqueleto con php arco MakeModel UserModel.

Núcleo

ArtifyStencil · vistas

ArtifyStencil renderiza plantillas de app/Views pasándoles datos. Separa la lógica del controlador de la presentación.

$stencil = new ArtifyStencil();
echo $stencil->render('login', [
    'login' => $login,
]);
Escapa siempre la salida. Al imprimir valores de usuario en una vista, usa el escape de Security para evitar XSS. Ver Seguridad.

Datos

Queryfy · constructor de consultas

Queryfy construye y ejecuta consultas SQL sobre PDO usando sentencias preparadas en todas sus operaciones, de modo que los valores nunca se concatenan en el SQL. Es la defensa de base contra la inyección SQL.

Operaciones básicas

$q = DB::Queryfy();

// SELECT con filtro
$q->where('estado', 'activo');
$filas = $q->select('noticias');

// INSERT
$q->insert('noticias', ['titulo' => $titulo, 'cuerpo' => $cuerpo]);

// UPDATE
$q->where('id', $id);
$q->update('noticias', ['titulo' => $titulo]);
Estado compartido. Una misma instancia de Queryfy acumula las condiciones where(). Si reutilizas el objeto para varias consultas seguidas, arrastrarás filtros de la consulta anterior (fue la causa del bug de tickets de almuerzo duplicados). Pide una instancia nueva por consulta lógica o limpia el estado entre llamadas.

Datos

Artify CRUD · mantenedores

El componente CRUD de Artify se obtiene con DB::ArtifyCrud() y genera formularios y mantenedores a partir de una tabla: define la tabla base, los campos que participan del formulario y los callbacks del ciclo. Es la pieza más productiva del framework.

Ejemplo real · formulario de acceso

Este es el patrón tal como se usa hoy en el proyecto (el formulario de login): se declaran los campos del formulario, se registra un callback que se ejecuta antes de procesar, se fija la tabla base y se renderiza.

$artify = DB::ArtifyCrud();

$artify->formFields(['usuario', 'password']);
$artify->addCallback('before_select', [$this, 'login']);
$artify->setLangData('login', 'Ingresar');

$login = $artify->dbTable('usuario')->render('selectform');

Métodos del ciclo

MétodoRol
dbTable(tabla)Fija la tabla base sobre la que opera el CRUD.
formFields([...])Define qué campos participan del formulario.
addCallback(evento, cb)Engancha lógica al ciclo (p. ej. before_select).
render(modo)Genera la salida del componente (formulario, mantenedor, etc.).

Callbacks

Los callbacks permiten intervenir el ciclo: por ejemplo, hashear una contraseña antes de insertar, o autenticar en el formulario de login.

$artify->addCallback('before_select', [$this, 'login']);
Por completar. Documenta aquí el resto de la API del CRUD (validaciones, acciones por fila, cargas de archivos) a medida que la confirmes contra el código, para que un mantenedor futuro tenga la referencia completa.

Seguridad

Sesión y autenticación

SessionManager centraliza el manejo de sesión: arranque, expiración por inactividad, rotación del identificador y cierre. El login usa password_verify y regenera el ID de sesión para evitar la fijación.

Flujo de login

if (password_verify($pass, $hash[0]['password'])) {
    SessionManager::startSession();
    SessionManager::regenerar();        // anti-fijación
    Security::limpiarIntentos($idIntento);
    // ... acceso concedido
} else {
    Security::registrarIntentoFallido($idIntento);
    echo 'El usuario o la contraseña no coinciden.';
}

Freno de fuerza bruta

El login se bloquea tras 5 intentos fallidos por IP + usuario en 15 minutos, con un pequeño retardo por fallo. El mensaje de error es genérico para no revelar si el usuario existe.

Guardián. Recuerda validar SessionManager::get('usuario') en el constructor de cada controlador de administración.

Seguridad

Seguridad · clase Security

Toda la postura de seguridad de la aplicación está concentrada en App\core\Security, que se arranca al inicio de cada petición con Security::boot(). Concentrarla en un solo lugar hace que auditarla y endurecerla sea directo.

Qué hace boot()

  • Envía las cabeceras de seguridad y la política CSP.
  • Configura la cookie de sesión: HttpOnly, SameSite=Lax, Secure bajo HTTPS.
  • Oculta los errores en producción (APP_DEBUG=false).

Cabeceras enviadas

CabeceraPropósito
Content-Security-PolicyRestringe orígenes de scripts, estilos y recursos.
X-Content-Type-Optionsnosniff: evita adivinación de tipo MIME.
X-Frame-OptionsDENY: previene clickjacking.
Referrer-PolicyLimita la fuga de la URL de origen.
Strict-Transport-SecurityFuerza HTTPS (sólo bajo TLS).

CSRF · verificación de mismo-origen

Las acciones que modifican datos en el panel (alta, edición, borrado) exigen que la petición provenga del propio sitio (Security::mismoOrigen()). Combinado con la cookie SameSite=Lax, bloquea la falsificación de peticiones entre sitios sin necesidad de tocar el front-end.

Validación de Grid ID

El identificador de instancia de grilla se valida con Security::gridIdValido() (patrón alfanumérico estricto) antes de usarse, cerrando cualquier intento de path traversal.

Cargas seguras

Los archivos subidos reciben un nombre aleatorio (nombreArchivoSeguro) y se rechazan las extensiones ejecutables (extensionEjecutable, que además detecta dobles extensiones). El directorio de cargas sirve sólo una lista blanca de tipos y bloquea la ejecución de scripts por .htaccess.

Pendiente para el 10. Endurecer la CSP quitando 'unsafe-inline' de script-src: primero en modo Report-Only, migrar scripts en línea a nonces, y recién entonces retirarlo.

Seguridad

API REST y JWT

El framework expone una API REST por recurso (api/{tabla}) protegida con autenticación JWT y CORS por lista blanca de orígenes. El RestpController consume esos recursos para listar, insertar, actualizar y eliminar.

Restricción del modo query

La API incluye una operación capaz de ejecutar SQL crudo, gobernada por ALLOW_QUERY_EXECUTION. En producción debe permanecer en false: el sitio opera por recurso y no necesita SQL arbitrario.

# .env
ENABLE_JWTAUTH=true
ALLOW_QUERY_EXECUTION=false
CORS. No uses comodín * con credenciales: mantén la lista blanca de orígenes permitidos.

Herramientas

Consola arco

arco es la consola de línea de comandos del framework (equivalente a Artisan). Genera el esqueleto de controladores y modelos para no escribirlos a mano.

# crea app/Controllers/ReportesController.php
php arco MakeController ReportesController

# crea app/Models/ReporteModel.php
php arco MakeModel ReporteModel
Extiende arco. Documenta aquí cada comando nuevo que agregues, para que un mantenedor futuro conozca el catálogo completo.

Herramientas

Despliegue y checklist

El despliegue es en cPanel/Linux. La capa de servidor (redirección HTTPS, cabeceras y bloqueo de archivos sensibles) vive en el .htaccess raíz y en la carpeta de referencia servidor/.

.htaccess raíz

Reescribe todo hacia index.php, fuerza HTTPS, aplica cabeceras como respaldo del servidor y deniega la descarga de archivos sensibles (.sql, .env, error_log, composer.*, etc.).

Carpeta servidor/

Contiene la configuración TLS de referencia para Apache y Nginx y un script de inventario de cargas. No forma parte de la aplicación: guárdala fuera del public_html.

Checklist antes de publicar

  1. Ejecuta php -l sobre los archivos modificados y prueba el login en local.
  2. Define APP_DEBUG=false y ALLOW_QUERY_EXECUTION=false en el .env.
  3. Borra del webroot cualquier dump .sql, error_log o archivo de prueba.
  4. Verifica el TLS (objetivo A/A-) y confirma las cabeceras con la herramienta del área de ciberseguridad.
Gestión continua. Incorpora el sitio al inventario de activos con revisión periódica: la seguridad es un proceso, no un esfuerzo puntual.
